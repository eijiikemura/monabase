# Component test coverage map

This audit covers all **129 TSX files** under `src/`, including helper/entry files. It was reviewed on 2026-10-29; the shared Help menu and localized About links were added to the map on 2026-11-01, and AI request evidence coverage was updated on 2026-11-02. A test-file reference means the stated scenarios were inspected; references and test counts are **not** line/branch coverage percentages. Private configuration and credentials are not needed for these checks.

- **D**: the real component/view function and its callbacks/state are exercised by unit tests. Visual libraries/child boundaries may be replaced; this alone does not verify browser layout, React error propagation or native events.
- **W**: the component's real controller/hook/service has regression assertions. It is not a claim that the component's JSX is unit-rendered. The screen column records separate Electron coverage where present.
- **H**: a TSX helper or application entry point, rather than a standalone screen.
- **Electron**: the actual production renderer with simulated IPC, in [`sidebar.cjs`](../tests/e2e/sidebar.cjs). DB-specific rows run for the corresponding database. This does not prove real database privileges, network behavior or every operating system.

Internal components in a file share its row. For example, `StoredCommonUI` directly tests all three exported panels, `SqlWindowBottom` includes plan-node tests, and DB index/trigger/SQL subpanels are exercised through their parent screen. The map does not assert that every nested subpanel has its own isolated test.

The audit added tests for previously absent/thin direct coverage in small controls, AI settings/menu/reference selection, metadata panes, previews, stored panels/trace search, ER labels and result headers. Cross-tabulation and create-table screens now run with their **real controllers** in unit tests. Existing controller and Electron suites continue to cover the larger DB screens. No production component split was necessary.

Run `node --test tests/component-*.test.cjs` for the added focused checks, `npm run check` for all unit/regression checks, and `npm run test:ui` for production-renderer screen checks. The inventory test fails when a TSX file is added/removed without updating this map; it checks documentation completeness, **not behavioral coverage**.

Remaining limits: none of these assertions promises all branches, all nested components, visual appearance, assistive-technology behavior, real SQL execution or all OS/database versions. See [Testing](TESTING.md) for dedicated real-DB and disposable-environment suites. No automatic percentage gate is inferred from this inventory.
