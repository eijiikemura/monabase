# MonaBase Webサイト

[English](README.md) | **日本語**

AstroとStarlightで構築した、英語を基本とする製品トップページと日英対応の画面別マニュアルです。デスクトップアプリとは独立したnpmプロジェクトで、Webサイトの依存ライブラリを導入してもアプリ本体の依存関係には影響しません。

- [英語サイト](https://eijiikemura.github.io/monabase/) · [日本語サイト](https://eijiikemura.github.io/monabase/ja/)
- [製品README（英語）](../README.md) · [製品README（日本語）](../README.ja.md)

## ローカル開発

**Node.js 22.23.4以降**を使用してください（Node.js 26にも対応）。

```sh
cd website
npm ci
npm run dev
```

英語版は `http://localhost:4321/monabase/`、日本語版は `http://localhost:4321/monabase/ja/` で開けます。GitHub Pagesでは末尾の `/` がない `/monabase/ja` へのアクセスをスラッシュ付きのURLへリダイレクトします。

画面右上の言語切り替えでは、現在閲覧しているガイドに対応する言語版へ移動できます。Starlightが検索、モバイル用メニュー、目次、テーマ切り替えを提供します。検索インデックスは開発サーバーではなく、プロダクションビルド／プレビューで利用できます。

```sh
npm run i18n:extract
npm run check
npm run build
npm run preview
```

`check` では翻訳の完全性、Astro／TypeScriptの厳格な診断、コンテンツの回帰テストを実行します。`build` では対応する日英ページ、DBバッジ、`/monabase/` 配下のローカルリンク・アセットも検証します。`preview` は通常 `http://localhost:4321/monabase/` で本番ビルドを公開します。

## 製品紹介で伝える内容

トップページでは、ストアド・トリガーの実装、トレース解析、SQL作成、SQLチューニング、テストデータ作成という**5種類のAIワークフロー**、AIプロバイダーの選択、ストアドのソースとカスタムER図のGit版管理、本番環境を意識した安全な操作を紹介しています。

AIへ送信されるのは選択された文脈情報であり、AI自身がDB接続やSQL実行のツールを利用するわけではありません。メイン画面ではCommit／Rollbackによる明示的なトランザクション制御ができ、読取専用接続も併用できます。

サイトに記載する機能説明は、次の範囲を守ってください。

- トレース**再生**はライブの `DBMS_DEBUG` セッションに依存しませんが、実行時間や規模のあらゆる制限から解放されるわけではありません。
- AIは記録済みのトレースを基に擬似的に実行ステップを解析するのであり、DB上の処理を自律的にステップ実行するわけではありません。
- 読取専用接続やトランザクション制御は誤操作を減らしますが、DB側の権限設定を代替せず、DDL等の暗黙コミットを取り消せません。
- ER図の版管理の独自性は、競合製品との比較検証なしに断定しないでください。
- GitHub Releasesへのリンクがあるだけで、配布版が公開済みとは書かないでください。配布形式はWindows x64のインストーラー／ポータブル版とApple Silicon Mac用DMGで、Linux／Intel Mac向け配布はありません。信頼されたコード署名証明書がないGitHub配布のWindows版では、SmartScreen警告が表示される場合があります。

Trace、AI、ERなどのガイドでは、本文モデルの `sections`／`tables` を使って説明や操作表を追加できます。ページごとの表示順は `scripts/generate-content.mjs` とコンテンツモデルの特別な順序設定に揃えてください。トランザクション制御ガイドには、メイン接続のCommit／Rollbackと読取専用の制限を記載しています。

## コンテンツ編集と翻訳

- `src/content/site.ts` はトップページのテキストキー、ガイドの表示順、対応DBバッジ、概要、手順、DB別の注意点を定義しています。`t('sql_title')` のような**リテラルの英語キー**を追加してください。
- `src/i18n/en.json` と `src/i18n/ja.json` に、英語と日本語の文章を保存します。
- `website/` 内で **`npm run i18n:extract`** を実行すると、既存訳を上書きせずに新しいキーを追加できます。実際の `t()` 呼び出しをTypeScriptパーサーで抽出するため、コメントや例示コードは対象外です。機械翻訳は実行されません。新規キーは空文字列になるので、`check`／`build` の前に両言語を入力してください。不要になったキーは自動削除されないため、意図的に整理してください。
- `scripts/generate-content.mjs` がMDXとStarlightのUI拡張を生成します。`src/content/docs/`、`src/content/i18n/`、`.generated/`、`public/favicon.png` は生成対象なので直接編集しないでください。編集元はコンテンツモデルであり、ガイドの編集リンクもここを指します。
- デスクトップアプリにも独立した `npm run i18n:extract` がありますが、こちらのWebサイト用コマンドとは別です。
- 表示は `src/components/` と `src/styles/custom.css` で定義します。`../docs/screenshots/manual/en/` および `manual/ja/` のデモ画像はWebPへ最適化されます。ロゴとファビコンの生成元は `../src/assets/icon.png` です。
- `src/content/screenshots.ts` は日英のPNGを明示的にインポートします。画像を追加する場合は、このファイルへ言語・名前別の登録も追加してください。Webサイトルート外の画像を開発サーバー／本番ビルドの両方で扱うために必要です。未登録の画像は回帰チェックで検出します。

### 操作表と画面ガイド

ガイドでは、翻訳済みの見出し・説明・列名・行を持つ `tables` を指定できます。生成時に列数を検証し、縦棒をエスケープします。スマートフォンなど幅の狭い画面では、キーボード操作にも対応した横スクロール領域で表示します。

各画面の内容は以下のとおりです。数値は既存の詳細表の行数を示します。新しいガイドを追加した際には、この一覧と実装の整合性も確認してください。

- **データ生成：** 各種設定表とAIを使った注文データのシナリオ。
- **設定：** 5つのアプリタブにある17項目と保存・キャンセル・初期値適用を含む6表。変更による影響、再接続／再表示の必要性、独立したAIプロバイダーダイアログを説明。
- **SQL：** 実行・編集、結果、バインド、推定実行計画、チューニング、情報出力の6表・34行。アプリ内／外部AI利用の手順も説明。`tuning_info.txt` を作るだけではAIへ送信されません。
- **クエリビルダー：** ボタン、元表の配置、項目設定、集約、結合の5表・35行。列内OR／列間AND、集約前フィルター、結合方向、対応範囲を説明。
- **クロス集計：** 元データ、軸、変換／グループ化、集計、絞り込み、グラフ・結果出力の5表・34行。月次合計や整数区間の例、DB別COUNT差異、列カテゴリ200件上限などを記載。
- **テーブル：** フィルター、ページ切替、データ編集、インポート／エクスポート、構造、外部キー、自動ER図、統計、DDL／Gitソースの6タブを8表・50行で説明。下書きと適用済みの状態を区別。
- **ビュー：** データ、定義編集、Git履歴、カタログ情報など4タブを5表・36行で説明。読み取り範囲やエクスポート、コンパイル診断、DB変更とGit操作の違いも記載。
- **インデックス：** 既存インデックスの3タブと新規作成フォームを6表・35行で説明。Oracle固有の設定、既存インデックスの変更範囲、削除制約、DB固有の統計を記載。存在しないリビルド機能やGit履歴エディタを掲載しないでください。
- **CHECK制約：** 編集／ソース、新規作成の4表・24行。Oracleの有効／無効、PostgreSQLの名称変更範囲、NULL・境界値を説明。
- **プロシージャ・関数：** ソース、条件付きトレース解析、Git版管理、情報、引数・結果の5表・36行。コンパイル・実行・再生・Gitを明確に区別。
- **パッケージ：** Oracleの仕様部／本体の違いと条件付き4タブを6表・40行で説明。メンバー選択、オーバーロード、引数、トレース、Git、情報を網羅。
- **型：** ソース、Git版管理、情報、PostgreSQLの変更ダイアログの6表・35行。Oracle TYPEのコンパイルとPostgreSQL ENUM／複合型の違いを記載。
- **シーケンス：** 設定、ソース、情報の6表・32行。設定保存と実際の番号再始動、Oracleのオプション、PostgreSQLのOWNED BY列関連を区別。

デスクトップのMona／Simple／Darkスタイルは「はじめに」の `guides/styles/` にまとめ、トップページ下部からも案内しています。デスクトップ側のテーマとWebサイト側のテーマは別です。`sections` の各項目には説明に添える任意の `image` を指定できます。

現在、コンテンツモデルには**各言語37ページ**（トランザクション制御、お問い合わせ、プライバシーポリシーを含む）があります。Oracle専用／PostgreSQL専用の画面では、対応するDBバッジだけを表示します。画像付きのガイドでは言語に合ったスクリーンショットを使います。

`docs/screenshots/manual/{en,ja}/` の既存70点のデモ画像は、架空のデータと模擬DB／AI応答を使って本番用レンダラーで撮影したもので、撮影には実DBや外部AIサービスを利用していません。お問い合わせ／プライバシーポリシーなどの情報ページは、アプリ画面の画像を必要としません。従来のREADME用画像も `docs/screenshots/` に維持しています。

画像の更新範囲と撮影方法は[スクリーンショットの記録](../docs/SCREENSHOTS.md#localized-manual-screenshots)を参照してください。ガイドが両言語に存在すること、および生成HTML内の画像と言語の整合性をテストしています。DB対応可否はバッジだけで判断せず、アプリ本体の実装と説明を一致させてください。

## お問い合わせ・プライバシー・アクセス解析

日英で `guides/contact/` および `guides/privacy-policy/` を公開する構成です。「はじめに」カテゴリの末尾は、サイドバーとトップページの両方で **スタイル → 設定 → お問い合わせ → プライバシーポリシー** の順にしています。

お問い合わせはGitHub Issues、GitHub Discussions、GitHubの非公開脆弱性報告、XのDM（`https://x.com/eijiikemura`）へ振り分けます。メール窓口と問い合わせフォームはありません。Xではすべてのアカウントからのメッセージリクエストを受け付け、スパムフィルターで確認しますが、返信は保証しません。認証情報・非公開データ・脆弱性を公開投稿へ含めないよう案内してください。

`astro.config.mjs` のStarlight `head` には、**同意後に読み込むGA4**（測定ID `G-2MV9LLEF3H`）を実装しています。訪問者が同意した場合にのみGoogle Analyticsのタグを読み込み、拒否してもサイトを利用できます。日英対応の設定UIから、後で選択を変更できます。解析の動作を変更する際には、必ずプライバシーポリシーの説明も更新してください。これは**Webサイトのアクセス解析**であり、デスクトップアプリの利用状況収集ではありません。

## GitHub Pages

公開先のリポジトリは **`eijiikemura/monabase`** です。公開前に名前・大文字小文字、`.github/workflows/website.yml` の配布許可リスト、`src/config.ts` のリポジトリ・ダウンロード・編集リンクを確認してください。GitHubリポジトリやReleasesへのリンクがあるだけで、アプリ本体が公開済みとは限りません。

1. ソースとWebサイトのロックファイルを、新しいリポジトリの `main` ブランチへPushします。
2. **Settings → Pages → Build and deployment** で **GitHub Actions** を選択します。
3. **Website** ワークフローのビルドが成功したことを確認します。
4. 既定ブランチで **Actions → Website → Run workflow** を実行して公開します。
5. 日英ページ、言語切替、検索、モバイル表示を確認します。
   - `https://eijiikemura.github.io/monabase/`
   - `https://eijiikemura.github.io/monabase/ja/`

通常のPushでは検証・ビルドと7日間有効なPages成果物のアップロードが行われ、**自動デプロイはしません**。公開は指定された公開リポジトリからの手動実行で行います。非公開テストリポジトリでは公開せずにビルドできます。ビルドジョブはリポジトリへの読取権限だけを持ち、Pages／OIDCへの書込権限は独立した公開ジョブだけに付与します。公式GitHub ActionsはコミットSHAへ固定し、PR起動やPersonal Access Tokenは使用しません。デプロイ時にはプロジェクトコードを実行しません。

デスクトップアプリのCI、実DB統合テスト、アプリ本体のリリースワークフローはそれぞれ独立しています。**Webサイトの公開はデスクトップアプリのリリースを伴いません。**
